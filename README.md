Прототип интерактивной карты торгового центра на three.js

В прототипе реализован базовый функционал, включающий в себя:
1. Генерацию магазинов случайного размера.
2. Создание из массива объектов(мешей) THREE и добавление их на сцену
3. Упаковку магазинов на сетке алгоритмом shelfPacking(по полкам)
3. Переключение между двумя проекциями
4. Выбор объекта

Установка и запуск:  
Node.js 18+ (проверял на 24.14.1)  
npm install  
npm run dev  

Переключение камер:  
Клавиша "1" - перспективная  
Клавиша "2" - ортогональная  

Интерактивность:  
Наведение - убираем прозрачность, увеличиваем эмиссию(с плавностью!)  
Клик - вывод в консоль id, name, position + ободка(edges)  

Структура:  
constants.js - константы  
main.js - точка входа, инициализция сцены, камер, света  
renderer.js - создание WebGL  
scene.js - создание сцены и сетки  
camera.js - создание камер  
lights.js - свет  
layout/shelfPacking.js - алгоритм упаковки  
interaction.js - обработка ховера и клика  
generate.js - генерция магазинов   
styles.css - стили(лейблов)  

Длинные названия:  
Обрезаем многотичем (text-overflow: ellipsis; ), При выделении показываем целиком. Добавил стрелку(долго выбирал ее)

Архитектура:  
Упаковка объектов: shelf packing. Выбрана потому что самая простая.   
Алгоритм:  
Сортируем объекты по глубине(в 2d высота) для более плотной упаквоки
Есть контейнер фиксированный ширины. Делаем обход по отсортированным по глубине объектами(магазинам). Если магазин по ширине помещается в ряд - ставим, сдвигаем X на ширину магазина. Если не помещается - начинаем новый ряд: обнуляем X, свдигаем Z на максимальную глубину предыдущего ряда. После добавления каждого магазина обновляем максимальную глубину ряда.

Оптимизация:  
При увеличении количества объектов нужно будет изменить логику ховера и селекта и сохранять предыдущий выбранный объект, думаю до 10000 тысяч объектов разница практически не заметна.

Для текстовых подписей - переход на спрайты. Если сцена большая, то текст скрываем у дальних объектов, показываем для них иконки(лого/пиктограммы)из атласа, при зуме у ближайших к камере магазинов отображать текст(LOD).

Обработка кликов объединенного меша: хранение массива bounding boxes с границами каждого объекта и сравнение с лучом рейкаста.

Для поиска по id нужен Map(ну или просто обычный объект). Для поиска по координатам - сетка, если достаточно равномерное распределение, в противном случае quadtree(никогда не ипользовал).
